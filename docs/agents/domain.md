# Domain documentation

Treat the scraper/importer pipeline and Astro site as one Badger Politics domain. Read the repository guidelines, README, and relevant methodology/runbooks before architectural exploration.

When present, consult root `CONTEXT.md` for terminology and `docs/adr/` for architectural decisions. If a future `CONTEXT-MAP.md` defines separate contexts, follow its relevant pointers. Missing domain files do not block work; create them only when the task establishes useful terminology or decisions.

Use existing domain terms consistently. Surface conflicts with documented decisions. Keep exploratory notes and draft decisions under `.private/`; put only reviewed, public-safe terminology and decisions in tracked documentation.
